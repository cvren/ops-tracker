# v0.3.0 to M4 Handoff

## Current state

- `ops-tracker` `v0.3.0` is feature-complete locally
- The shipped surface includes manager dashboard drill-down, admin bulk queue operations, templates, recurring schedules, and manual recurring generation
- `v0.2.0` collaboration flows remain the baseline and are still covered by validation

## What is verified locally

- Dashboard shows overdue, blocked, unassigned, review, due-soon, aging, workload, and bottleneck data from real task rows
- `/tasks` supports manager views and admin-only bulk updates
- `/templates` supports template create/edit, one-off task generation, recurring schedule create/edit, and manual `Generate now`
- Bulk, template, and recurring flows write `ActivityEvent` rows
- Duplicate recurring execution is blocked for the same schedule run slot
- Local validation passed:
  - `corepack pnpm install`
  - `docker compose up -d`
  - `corepack pnpm exec prisma generate`
  - `corepack pnpm exec prisma migrate deploy`
  - `corepack pnpm db:seed`
  - `corepack pnpm lint`
  - `corepack pnpm typecheck`
  - `corepack pnpm test`
  - `corepack pnpm test:e2e`
  - `corepack pnpm build`

## What still needs observation

- Current branch-head GitHub-hosted `ci` still needs to be observed on the pushed reconciliation commit
- The branch currently has no upstream configured, so hosted observation depends on pushing `codex/v0.3-m3`

## Shipped boundary to preserve in M4

- `Membership.role` remains the effective authorization boundary
- Manager-console mutations are still admin-only
- The product remains single-workspace
- Recurring generation remains manual in `v0.3.0`; do not add background jobs casually
- Queue drill-down intentionally stays on the existing `/tasks` surface

## Deferred to M4

- Member-safe permission expansion for manager-console actions
- Background recurring execution, reminders, or notification fan-out
- Queue or worker infrastructure
- Business-day / holiday / advanced recurrence logic
- Cross-workspace templates or template versioning
- Analytics, SLA prediction, or automation-builder scope

1. Push the reconciled branch and observe hosted `validate` plus `e2e`
2. Merge the reviewed branch into `main`
3. Tag the merge commit as `v0.3.0`
4. Publish the GitHub Release using `RELEASE_NOTES_v0.3.0.md`
5. Start M4 only after the release tag and notes are published
